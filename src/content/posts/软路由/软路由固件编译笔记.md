## 五、路由器当前状态(2026-10-26 凌晨,与编译相关)

- ua2f 4.10.2-r1 / ua3f 3.7.0-r1 / mentohust 0.3.1-1 三个 ipk **已装但全部 disabled、无进程**(用户要求先装不启用),落在 U 盘沙箱层,重置沙箱即整体消失
- **坑 1**:这三个包的 postinst 都会自动注册自启,装完必须立刻 `/etc/init.d/<名> disable && stop`
- **坑 2**:mentohust 无配置时运行会进交互式向导(空 stdin 会乱选网卡),启用前必须先写好配置
- **坑 3**:UA2F 生效前提是**关闭 flow offloading(流量卸载)**,该机当前开着 flow offloading——启用时二选一
- 已知网内怪癖:clash 只监听 :::7890(v6),本机 curl 127.0.0.1:7890 挂起,测代理要走日志或局域网设备

## 六、编译流程(到时照抄)

```
git clone https://github.com/istoreos/istoreos.git && cd istoreos
git checkout <24.10.5 对应 tag>
./scripts/feeds update -a && ./scripts/feeds install -a
# 把 minieap/ua2f/ua3f 的 package 源码放 package/ 下(自己写 Makefile 或用上游现成的)
make menuconfig   # Target=x86/64;勾 TARGET_ROOTFS_EXT4FS/SQUASHFS、需要的包、luci-app
make -j12 V=s     # 首次约 1.5~3 小时;之后增量 20~40 分钟
# 产物: bin/targets/x86/64/*.combined-ext4.img 与 sysupgrade.bin
```

- 刷机(到时候单独征得用户同意):LuCI/iStore 用 sysupgrade **保留配置**升级;刷前备份 /etc/config 与沙箱里的自制配置(如 Argon dark.css 补丁、tune-nic.sh)
- 编译本身零风险,完全不碰路由器

## 十一、NFS/rpcbind 完整修复链(2026-10-26 05:30,全部已通)

NFS 全套(luci-app-nfs + nfs-kernel-server + rpcbind)拉出 libtirpc 依赖链,连环四个坑逐一破:

1. **host 编译失败**=libtirpc 1.3.4 的 K&R 函数声明撞 gcc15/C23 → 升级 1.3.7(Hash=b47d3ac1...)→ 上游已修
2. **旧 clang 补丁打不上**=001-clang.patch 对 1.3.7 源码冲突 → 删 feeds/packages/libs/libtirpc/patches/ 整个目录(上游已修同一问题)
3. **target 库缺符号**=`getrpcbynumber/getrpcbyname` 没导出 → 1.3.7 默认关 RPCDB,Makefile 加 `CONFIGURE_ARGS += --enable-rpcdb` 和 `HOST_CONFIGURE_ARGS += --enable-rpcdb`(两行都要)
4. **打包步骤 Error 1(Makefile:77,provides 目标)**=Ubuntu 26.04 用 uutils coreutils:`mktemp -d -t X` 不回退 /tmp;且 make 4.4 对 package-pack.mk 的双目标规则(provides 与 PACK 共用 recipe)会**每个目标各跑一遍**,第二遍拿不到 PACK 的 CONTROL 导出 → 打出空 `__.ipk` 失败
   - 修 A:`/usr/bin/mktemp` 换成 busybox软链(原 uutils 备份在 /usr/bin/mktemp.uutils)
   - 修 B:`include/package-pack.mk` 四行 export 的目标从 `$$(PACK_$(1))` 扩成 `$$(PACK_$(1)) $(PKG_INFO_DIR)/$(1).provides`(备份 include/package-pack.mk.bak-exports)
5. 通用教训:Ubuntu 26.04(uutils coreutils + make 4.4)与 OpenWrt 24.10 构建脚本系统性不兼容,上面两条补丁是必需品;更省心的替代=用 Ubuntu 24.04 LTS 的 VM

验证标准:`nm -D staging_dir/target-x86_64_musl/usr/lib/libtirpc.so.3.0.0 | grep getrpcby` 见 T 符号,rpcbind_1.2.6-r2_x86_64.ipk 产出为通过。

**2026-10-28 回环修复(UA3F_HELPER,用户批准后执行)**

- 现象:路由器本机 TCP 到 127.0.0.1 超过 8KB 卡死(同一 `/www/cups.pdf`:127.0.0.1 只收到 8192B 后 25s 超时,从 LAN 走 192.168.10.1 0.1s 下完 228KB)。UA3F tproxy 表本身已 `return 127/8`,所以只能是 postrouting 的 `HELPER_QUEUE` 把回环包排队到用户态 10301 改写 TTL/IPID/TS/TCPWIN 时搞坏。副作用:从路由器本机测节点/下载会误判成"所有节点卡在 ~10KB"
