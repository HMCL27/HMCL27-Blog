# 2022 物联网竞赛通信文档

## 一、前端接收的数据（硬件 / 后端 → Web / 手机 APP）

### 1. subDrinkData 饮水机实时综合数据

前端与硬件、后端通信，定时上报单台饮水机全部传感、执行、运行状态，页面实时展示

字段说明：

- `ID`：饮水机唯一编号
- `TIME`：系统时分秒时间
- `T1`：常温水水箱温度 (℃)
- `T2`：热水箱温度 (℃)
- `V1`：水源水质检测电压 (V)
- `V2`：净水水箱水质检测电压 (V)
- `TDS1`：水源水质 ppm
- `TDS2`：出水水质 ppm
- `Flow`：累计饮水量
- `Wh`：高水位 1 = 达到高水位 / 0 = 未到
- `W1`：低水位 1 = 低于低水位 / 0 = 正常水位
- `M`：加压水泵状态 1 运行 / 0 停止
- `P`：加热模块 1 加热 / 0 停止
- `S1`：常温水电磁阀 1 开 / 0 关
- `S2`：热水电磁阀 1 开 / 0 关
- `Status`：整机状态 0 复位 / 1 暂停 / 2 正常

```json

{
  "ID": "2001",
  "TIME": "15:20:33",
  "T1": 24.5,
  "T2": 62,
  "V1": 2.1,
  "V2": 3.6,
  "TDS1": 48,
  "TDS2": 22,
  "Flow": 1250,
  "Wh": 0,
  "W1": 0,
  "M": 1,
  "P": 1,
  "S1": 0,
  "S2": 1,
  "Status": 2
}
```

### 2. subCardRecord 刷卡饮水记录

刷卡取水后硬件上报，后端入库，前端实时弹窗展示饮水流水

- `CardNumber`：校园卡卡号

```json

{
  "ID": "2001",
  "TIME": "15:21:10",
  "CardNumber": "202201001",
  "SingleFlow": 120
}
```

### 3. subTip 故障 / 水质告警推送

前端、服务器、硬件互通，异常实时推送 APP 弹窗

告警码定义：

- `STATUS=1`：Error1 水位传感器故障（高低水位同时触发）
- `STATUS=2`：Warning1 净水 TDS2＞100，水质不合格

```json

{
  "ID": "2001",
  "TIME": "15:22:05",
  "STATUS": 2
}
```

### 4. subResetMsg 饮水机上电复位消息

设备上电自动发送，后端收到后同步下发时间与整机状态指令

```json

{
  "ID": "2001",
  "TIME": "15:00:00"
}
```

### 5. subHistoryData 历史数据查询返回

前端调用 pubHistory 后，后端返回该饮水机历史运行、饮水流水数组

```json

[
  {
    "ID": "2001",
    "TIME": "14:10:22",
    "T2": 60,
    "TDS2": 20,
    "Flow": 860
  },
  {
    "ID": "2001",
    "TIME": "14:35:16",
    "T2": 63,
    "TDS2": 23,
    "Flow": 1040
  }
]
```

### 6. subUserHistory 学生个人饮水统计数据

前端按卡号查询后，后端返回该学生全部饮水记录

```json

[
  {
    "ID": "2001",
    "TIME": "14:35:16",
    "CardNumber": "202201001",
    "SingleFlow": 180
  },
  {
    "ID": "2002",
    "TIME": "15:10:05",
    "CardNumber": "202201001",
    "SingleFlow": 125
  }
]
```

## 二、前端发送的数据（Web/APP → 后端 / 硬件）

### 1. pubMachineCtrl 远程控制饮水机整机状态

修改设备运行模式：0 复位 / 1 暂停 / 2 正常

```json

{
  "ID": "2001",
  "Status": 1
}
```

### 2. pubHeatConfig 设置热水温度阈值 TH

下发至硬件，掉电保存参数，范围可自定义

```json

{
  "ID": "2001",
  "TH": 65
}
```

### 3. pubTime 同步系统时间至饮水机

设备复位后后端下发，也可前端手动同步时间

```json

{
  "ID": "2001",
  "TIME": "15:25:40"
}
```

### 4. pubHistory 查询饮水机历史运行数据

search=0 查询设备运行数据；search=1 查询全部饮水流水

```json

{
  "ID": "2001",
  "search": 0
}
```

### 5. pubUserSearch 查询指定学生全部饮水记录

按卡号检索跨设备饮水数据

```json

{
  "CardNumber": "202201001"
}
```

### 6. pubTipUpload 后端存储告警记录

硬件上传告警后，后端转发存入数据库，供历史查询读取

```json

{
  "ID": "2001",
  "TIME": "15:22:05",
  "STATUS": 2
}
```

## 三、巡检装置直连通信（巡检设备 ↔ 饮水机，点对点无线）

### 巡检端接收 subInspectData

巡检设备近距离读取饮水机本地数据，不走服务器

```json

{
  "ID": "2001",
  "V1": 2.1,
  "V2": 3.6,
  "AlarmCode": 0
}
```

AlarmCode：0 无告警 / 1 水位故障 / 2 水质超标

### 巡检端下发 pubInspectGet

巡检设备发起读取请求

```json

{
  "ID": "2001"
}
```

## 四、后端业务交互规则

1. 收到`subResetMsg`复位消息处理流程
    
    - 自动下发`pubTime`同步系统时间
    - 读取后台存储的该饮水机`Status`，下发`pubMachineCtrl`同步整机状态
    
2. 断网缓存机制
    
    - 饮水机断网期间缓存至少 2 条刷卡、告警数据；恢复联网后自动批量上报`subCardRecord`、`subTip`
    
3. TDS 自动计算逻辑（硬件本地计算后上报）
    
    - TDS1 = 110 * ((5 - V1) / V1)
    - TDS2 = 110 * ((5 - V2) / V2)
    - TDS2＞100 自动触发 STATUS=2 水质告警
    
4. 电磁阀互斥约束
    
    - 硬件收到出水指令后，保证 S1、S2 不会同时为 1；切换时自动关闭另一路阀门
    
5. 组委会交互（HTTP）
    
    后端定时 POST 完整`subDrinkData`数据至裁判判定接口，返回：

```json

{"code":0,"msg":"数据采集正常"}
```

code=1 代表数据缺失、逻辑异常扣分
