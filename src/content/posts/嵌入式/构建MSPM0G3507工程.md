# 构建 MSPM0G3507 工程
> 基于本机实测：Keil MDK Plus 5.43（AC6.24）+ MSPM0 SDK 2.02.00.05 + SysConfig 1.21.1 + MSPM0 DFP 1.3.1，编译 0 Error / 0 Warning。

---

### 和 STM32 那篇最大的区别

STM32 标准库是"把 CMSIS、启动文件、外设库拷进工程"；MSPM0 不能这么干：

- TI **不建议从零新建工程**（官方原话：从头建不会自动添加必要的器件支持文件），推荐**从 SDK 的空示例派生**；
- 头文件、`driverlib.a` 都直接引用 SDK 目录，**工程必须放在 SDK 根目录下**（和 `source`、`tools` 同级），否则相对路径全断；
- 外设配置不是手写，是 `.syscfg` 图形化配置后由 SysConfig **生成** `ti_msp_dl_config.c/h`。

### 第一阶段：准备工作

| 项 | 本机位置 / 版本 |
| --- | --- |
| Keil MDK | `C:\aHMCL\Tool\Keil_v5.43`（≥5.38，AC6） |
| MSPM0 SDK | `C:\aHMCL\Tool\code\TI\mspm0_sdk_2_02_00_05` |
| SysConfig | `C:\aHMCL\Tool\code\TI\SYSCONFIG121`（**1.21.1**，别用 1.28，引脚号≥16 会解析错） |
| 器件包 | `MSPM0G1X0X_G3X0X_DFP 1.3.1`（已装） |
| 调试器 | J-Link / DAP-Link（板子只有 SWD 排针，**不能用 ST-Link**） |

---

### 第二阶段：复制空示例

源目录：`<SDK>\examples\nortos\LP_MSPM0G3507\driverlib\empty`

把它整个复制到 **SDK 根目录**下并改名，例如：

```text
C:\aHMCL\Tool\code\TI\mspm0_sdk_2_02_00_05\
├── source\                 # SDK 自带，不动
├── tools\                  # SDK 自带，不动
└── my_project\             # 复制出来的工程（必须和 source 同级）
    ├── my_project.c        # 原 empty.c，改名
    ├── my_project.syscfg   # 原 empty.syscfg，改名
    ├── ti_msp_dl_config.c  # 首次编译由 SysConfig 生成
    ├── ti_msp_dl_config.h
    └── keil\
        ├── my_project_LP_MSPM0G3507_nortos_keil.uvprojx
        ├── my_project_LP_MSPM0G3507_nortos_keil.uvoptx
        ├── startup_mspm0g350x_uvision.s
        ├── mspm0g3507.sct
        └── Objects\        # 编译输出
```

复制后要做的三件事：

1. 把 `.uvprojx` / `.uvoptx` 里的 `empty` 全部替换成 `my_project`（工程名、文件名）；
2. 把 `.uvprojx` 里所有 `../../../../../../` 替换成 `../../`（空示例原本嵌在 SDK 的 6 层目录里，挪到根目录后层级变了，Include、链接库、SysConfig 预编译三处都写着它）；
3. `.syscfg` 里 `@cliArgs` 的工程名不用改，改文件名即可。

### 第三阶段：Keil 工程配置

打开 `keil\*.uvprojx`，逐项核对：

#### Groups 与文件

| Group | 文件 |
| --- | --- |
| Source | `..\my_project.c`、`..\my_project.syscfg`、`startup_mspm0g350x_uvision.s`、`..\ti_msp_dl_config.c/h` |

后面写外设可以自己加 `BSP` 组。

#### C/C++ (AC6)

```text
Include Paths:
..\..\source\third_party\CMSIS\Core\Include
..\..\source
..                      ← 工程根目录（BSP 里 include "ti_msp_dl_config.h" 靠它）

Define:
__MSPM0G3507__
```

> `..\..\` 是相对 `keil\` 目录往上两级，正好回到 SDK 根。这就是"工程必须放 SDK 根目录下"的原因。

#### Linker

```text
Scatter File:     .\mspm0g3507.sct
Misc controls:    ..\..\source\ti\driverlib\lib\keil\m0p\mspm0g1x0x_g3x0x\driverlib.a
```

#### Before Build（SysConfig 预编译）

在 `User` 选项卡的 Before Build 填：

```bat
cmd.exe /C "$P../../tools/keil/syscfg.bat '$P' my_project.syscfg"
```

它会在每次编译前按 `.syscfg` 重新生成 `ti_msp_dl_config.c/h`。

注意：SDK 里 `tools\keil\syscfg.bat` 顶部的 `SYSCFG_PATH` 要指向 **1.21.1** 那份，本机已改成 `SYSCONFIG121`。

#### Device / Output

- Device：`MSPM0G3507`（DFP 1.3.1）
- Output：勾选 **Create HEX File**

### 第四阶段：编译

IDE 里点 Rebuild，或命令行（VSCode 用的就是这条）：

```bat
"C:\aHMCL\Tool\Keil_v5.43\UV4\UV4.exe" -b "my_project_LP_MSPM0G3507_nortos_keil.uvprojx" -j0 -o build.log
```

实测日志（以 `tmx_01_led` 为例，路径是你的实际路径）：

### 第五阶段：烧录与调试

天猛星 SWD 引脚：**PA19 = SWDIO，PA20 = SWCLK**（板载无调试器，需外接 J-Link/DAP-Link）。

1. Options → **Debug** → 选 `J-LINK / J-TRACE Cortex` → Settings → Port 选 **SW**，能看到 Cortex-M0+ 即连上；
2. **Flash Download** → Add → 选 MSPM0G3507 的 Flash 算法（DFP 自带）；
3. 点 **Load (F8)** 烧录，或 Start/Stop Debug Session 单步。

串口调试：CH340 接 **PA10 = U0TX，PA11 = U0RX**，波特率按例程设置。

> 这一步本机没接板子，属于未实测部分，仅供参考。

---

### 天猛星板载 LED

板载 LED 在 **PB22**，低电平点亮。`.syscfg` 里配 `PORTB / PIN_22`，代码里用 `DL_GPIO_setPins / clearPins` 翻转即可，参考资料里的 `tmx_01_led`。

### 快速参考表

| 关键项 | 取值 | 要点 |
| --- | --- | --- |
| 工程位置 | `<SDK>\my_project\` | 必须和 `source` 同级 |
| 启动文件 | `startup_mspm0g350x_uvision.s` | G350x 系列通用 |
| 链接脚本 | `mspm0g3507.sct` | Flash 128KB @0x0，RAM 32KB @0x20200000 |
| 宏定义 | `__MSPM0G3507__` | 决定头文件里的器件寄存器定义 |
| 库 | `driverlib.a` | 预编译库，不拷源码 |
| 预编译 | `syscfg.bat` | 改 `.syscfg` 后自动重生成 |
| 编译器 | AC6 | 与 AC5 不兼容，例程都是 AC6 |

### ✅ 验证成功的标志

1. 编译：**0 Error(s), 0 Warning(s)**，Objects 下有 `.axf` 和 `.hex`
2. 下载：J-Link 能识别到 Cortex-M0+ 并烧录成功
3. 运行：LED 按预期闪烁，串口有输出

### 踩坑记录

- 例程直接复制到桌面/其他盘 → `ti_msp_dl_config.h` 找不到（相对路径断了）
- 文件夹改名后 → 工程里写死的 `..\..\旧名字` include 路径要一起改
- `.syscfg` 改了引脚但没重新生成 → 代码行为还是旧的，必须让预编译跑一遍
- SysConfig 1.28 配 PB22 → 被解析成 GPIOC.2，换回 1.21.1
